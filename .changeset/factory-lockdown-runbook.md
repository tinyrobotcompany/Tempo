Add factory tooling (operator runbook: docs/FACTORY_RUNBOOK.md, delivered separately) for locking down an ESP32-P4 board: a verified whole-flash backup and guarded restore (`scripts/factory-backup.sh`), a lockdown script that burns Secure Boot v2 and Development-mode flash encryption eFuses plus the identity HMAC key in Espressif's order (`scripts/factory-lockdown.mjs`, Node.js 22+), and an approval-gated, manually started workflow that registers one device's PUBLIC identity key (`scripts/factory-register.sh`). Everything is a dry run by default. Each device step needs its own typed confirmation, and keys are passed to espefuse through an inherited file descriptor so they never touch disk. The firmware build itself is unchanged and no device has been touched. The lockdown script runs on macOS only. It requires the signed production build from `scripts/secure-build.mjs` (layout ab-8mb-secure-v1, partition table at 0x10000) and uses that script's `check-config` as its configuration gate, and both a release and an independent backup Secure Boot public key. The backup key's digest goes in the second Secure Boot slot, and only the third slot is revoked. Validated with mocked tools and a full rehearsal against espefuse virtual ESP32-P4 v3.0 eFuses.
